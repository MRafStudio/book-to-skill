# `hermes/` — зеркало того, что ставится в профиль Hermes

Панель BOOK → SKILL (rail) и её REST-мост живут не в дереве пайплайна, а в
профиле Hermes. Здесь лежит их версионируемая копия: она же — то, что ставится
на другую машину. Разворачивают её два разных скрипта:

- **`tools/sync_hermes.py`** — для разработки на этой машине (двусторонний);
- **`tools/install_plugin.py`** — для установки на чужой (односторонний, создаёт
  `config.json` и проверяет окружение). См. `INSTALL.md` рядом.

## Что здесь лежит

| Файл в зеркале | Куда попадает | Кто подхватывает правку |
|---|---|---|
| `desktop-plugins/b2s/plugin.js` | `$HERMES_HOME/desktop-plugins/b2s/` | хот-релоад панели (сам, без действий) |
| `plugins/b2s/plugin.yaml` | `$HERMES_HOME/plugins/b2s/` | **только рестарт** dashboard |
| `plugins/b2s/__init__.py` | там же | **только рестарт** dashboard |
| `plugins/b2s/dashboard/plugin_api.py` | `$HERMES_HOME/plugins/b2s/dashboard/` | **только рестарт** dashboard |
| `plugins/b2s/dashboard/manifest.json` | там же | **только рестарт** dashboard |
| `plugins/b2s/dashboard/config.example.json` | **никуда** — шаблон | эталон для `config.json`, который пишет установщик |

`plugin.yaml` и `__init__.py` обязательны: без манифеста Hermes не считает
каталог плагином, без `__init__.py` с `register()` не монтируются маршруты
`/api/plugins/b2s/`. Раньше в зеркале их не было — установка на другую машину
давала молча нерабочую панель.

## Развернуть / проверить (разработка)

```bash
python tools/sync_hermes.py            # форк → профиль
python tools/sync_hermes.py --check    # показать дрейф, exit 1 если есть
python tools/sync_hermes.py --pull     # профиль → форк (забрать правку в git)
```

Профиль берётся из `--hermes-home`, иначе из `HERMES_HOME`, иначе ищется в
типовых местах (`%APPDATA%\Hermes`, `~/.hermes`, `<клон-рядом>/data/hermes`).
Машинного пути в коде нет — иначе зеркало не переносится на чужую машину.

**Что требуется в профиле, кроме файлов:** плагин должен быть включён
(`plugins.enabled` в конфиге Hermes), а в `manifest.json` стоять `api: true` —
без этого `plugins/b2s/dashboard/plugin_api.py` не смонтируется под
`/api/plugins/b2s/`. Проверка живости маршрута:

```bash
python tools/probe_route.py skills      # 200 + контрольный 404 = смонтирован
```

## `config.json` — локальный, в git не едет

Путь к клону и интерпретатор гейтов у каждой машины свои, поэтому файл **не
хранится в репозитории** (в `.gitignore`) и **не участвует в синхронизации**:

```json
{"fork": "<путь к этому клону>", "python": "<интерпретатор с trafilatura/bs4>"}
```

Создаёт его `tools/install_plugin.py`. Переопределяется переменными
`B2S_FORK` / `B2S_PYTHON`. Если файла нет и переменные не заданы, панель не
гадает: она отвечает 503 с инструкцией, что запустить (в коде нет пути чужой
машины).

## Чего тут нет и почему

- Файлы вне `desktop-plugins/` и `plugins/` (включая этот README и `INSTALL.md`)
  — документация зеркала: синхронизатор их не копирует, в профиле им делать
  нечего.
- `b2s_fetched/`, `staging/`, `backups/` — рабочие продукты, в `.gitignore`:
  скачанный текст может быть защищён авторским правом, а бэкапы скиллов —
  локальная страховка.
- Штатный конфиг Hermes (`config.yaml`) — не наша зона: единственное, что от
  нас нужно, — включённый плагин `b2s`.
