## Показ очищенного текста в панели (2026-09-12)

Жалоба владельца: «нажал „Анализ источника и очистка“ — а где увижу текст?» Панель после
шага 1 показывала только метрики (`chars/words/мусор`) и путь к файлу; сам текст жил
исключительно в `b2s_fetched/<slug>.md`. В прежнем виджете в песочнице (`dashboard/widget.html`)
такой блок был («Очищенный текст (что уйдёт в пайплайн)» + `<pre id="preview">`) — его и вернули,
но уже на штатном плагине.

Как сделано (три слоя, каждый без LLM):

1. **Ядро** — `tools/api.py`: `do_text(path="", offset=0, limit=0)`. Пустой `path` → берёт
   `source_file` последнего прогона из состояния; читает **только внутри `b2s_fetched`**
   (`_fetched_file`), иначе `{"ok": false, "error": …}` — панель не должна вытянуть произвольный
   файл с диска. Возвращает `path / chars / lines / offset / limit / returned / truncated / text`;
   `limit=0` — файл целиком. CLI: `python tools/api.py text [--limit N]`.
2. **REST** — `plugins/b2s/dashboard/plugin_api.py`: `POST /api/plugins/b2s/text` (`TextBody`).
3. **Панель** — `desktop-plugins/b2s/plugin.js`: **один** сворачиваемый блок
   «📊 Результат разбора» сразу под кнопкой шага 1, внутри три части — строка статуса,
   сводка последнего прогона и очищенный текст (объём + путь + предпросмотр `<pre>` с
   `max-height: 18rem`, кнопка «показать весь текст» → `limit=0`). Разрозненные блоки внизу
   панели убраны — раньше статус, сводка и текст были разбросаны по полотну.

Два пути к тексту — страховка: после прогона текст берётся **из самого отчёта**
(`report.preview`, 6000 символов — приходит вместе с метриками, досылать ничего не надо),
а `POST /text` уточняет объём и число строк и отдаёт файл целиком.

Грабли:

- **Новый маршрут плагина виден только после перезапуска процесса dashboard.** Роутеры

## План Б: свой HTTP-сервер дашборда (2026-09-11)

Панель предпросмотра Hermes — только витрина: мост `window.hermes` инжектится исключительно
в инлайн-виджет внутри чата (`inline-preview-directive.tsx`), в правом rail его нет, а HTML
в file-табе рендерится как исходник. Значит кнопки в панели физически не могут ничего
отправить агенту — это не баг виджета, а отсутствующая функция **у встроенной панели**
(у панели-плагина штатный мост есть, см. «План В»). Решение — **своя страница
по HTTP**: `_fork/tools/serve.py` (stdlib, слушает только `127.0.0.1`, переиспользует
`tools/dashboard.py`; шаблон `widget.html` остаётся один). Ветка `agent/url-dashboard`,
коммит `c87bcdc` (запушен).

Маршруты: `GET /` (страница с живыми данными), `GET /api/health`, `GET /api/state`,
`POST /api/rerun`, `POST /api/order` (очередь `staging/.orders/`), `POST /api/open`,
`POST /api/install`. В `widget.html` — ветка «страница открыта по HTTP»: кнопки шлют
`fetch` серверу и перезагружают страницу; прежний режим панели сохранён без изменений.

Проверено живьём **по логу сервера** (`dashboard/.serve.log`): из панели пришли
`POST /api/state` → `POST /api/rerun` → `GET /` — клик по кнопке реально доехал до сервера,
страница исполнила JS. Переключения стратегий в панели видны в логе теми же тремя запросами
(владелец сам их там выбирал).

Грабли:

- **На Windows `allow_reuse_address` разрешает повторный `bind` на тот же порт.** Пока на
  8765 висели два сервера, запросы обслуживал случайный процесс: ответы приходили то новым
  кодом, то старым — выглядело как «сервер врёт». Теперь
  `ThreadingHTTPServer.allow_reuse_address = False`, второй экземпляр падает с «порт занят».
  Проверка: `netstat -ano | grep '127.0.0.1:8765' | grep LISTENING` (должна быть одна строка).
- **Heartbeat не должен писать в строку статуса.** Опрос `/api/health` раз в 5 с затирал
  сообщение о результате прогона — снаружи это «ничего не произошло». Теперь heartbeat живёт
  в чипе состояния, строка статуса — только события.
- **Провал прогона не стирает последний удачный отчёт.** `raw-md` по HTML-странице даёт 0.0 с
  и «no plugin matched this URL»; теперь сервер отвечает `ok + warning` с объяснением
  по-русски («raw-md берёт только markdown-источники…»), а прежний отчёт остаётся на странице
  вместе со временем.
- **Пустое тело POST — почти всегда потерянный payload** (curl в MSYS его не донёс); для
  `/api/rerun` и `/api/order` теперь 400 вместо молчаливых дефолтов.
- **Логи сервера читать файлом** (`dashboard/.serve.log`), а не через мост `process_manage`:
  те приходят сжатыми. Лог очищается при старте — сразу видно, что страница ходит
  (`GET /api/health` каждые ~5 с).

## План В: штатный канал «панель → чат» через desktop-плагин (2026-09-11)

Разведка исходников Hermes дала штатный путь, закрывающий задачу без самодельного WebSocket:
у десктопа есть **плагины** (`$HERMES_HOME/desktop-plugins/<id>/plugin.js`), а плагину выдаются
`host.state.focusedSessionId` (id этой сессии), `host.request('prompt.submit', {session_id, text})`,
`host.onEvent('*')` и `ctx.register({area: 'panes'})` — своя вкладка в правом rail, а не Browser-таб.

Ключевая строка ядра (`tui_gateway/methods_prompt.py`, дословно):
`display_kind = "hidden" if params.get("display_kind") == "hidden" else None` с комментарием
*«Off-screen sends (widget intents) type the row so no client renders a bubble; whitelisted to
"hidden" — this RPC must not mint kinds.»* То есть «виджет шлёт интент в чат» — функция ядра,
а не обход. Канал подтверждён чтением кода; живая проверка — за владельцем.

Сделано: `D:\NEURO\Hermes\data\hermes\desktop-plugins\b2s\plugin.js` — панель BOOK → SKILL
(поля источник / имя скилла / категория, селекты стратегия / режим / язык, шаги 1 анализ источника,
2 черновик, 3 установка, «разобрать черновик», чип «агент работает»). Синтаксис проверен
`node --check` на копии `.mjs`. Плагин **вне репозитория** — форк остаётся чистым.

Грабли:

- **Плагин — ESM, который грузят, а не компилируют:** импорты только `@hermes/plugin-sdk`,
  `react`, `react/jsx-runtime`; JSX писать нельзя — только `jsx()` / `jsxs()`.
- **Экспорты SDK не выдумывать — читать `apps/desktop/src/sdk/index.ts`.** `StatusDot` = `good|muted|warn|bad`
  (не `busy|idle`), `Badge` variant `muted` (не `secondary`). Неверное значение даёт пустой контрол
  без ошибки — «работающий» плагин выглядит пустым.
- **Папку плагина приложение подхватывает само:** корень `desktop-plugins` и каждый `plugin.js` под
  fs-watch — новая папка грузится на change tick, сохранение файла даёт hot-reload. Старые оболочки
  поллят только видимые вкладки, им нужен «Reload desktop plugins».
- **CDP у packaged-десктопа закрыт** → DOM rail'а не прочитать. Честная проверка: владелец
  подтверждает, что вкладка появилась, и жмёт кнопку; доказательство — интент, прилетевший в чат.
- **`hermes plugins doctor` — про классические python-плагины**, про desktop-панель он молчит:
  чистый прогон ничего не говорит о нашей панели.
- `host.onEvent('*', fn)` возвращает disposer — возвращать его из эффекта.
- Документация: `hermes-agent/website/docs/developer-guide/desktop-plugin-sdk.md`.

Ограничение схемы прежнее: панель = пульт, прозу глав пишет агент в чате, поэтому шаги 1–3 всё
равно идут через чат. Свой HTTP-сервер (План Б) не выбрасываем — он остаётся витриной, но для
«панель инициирует работу» штатный путь теперь — плагин.

## Долив и замена: как это устроено (2026-09-12)

Владелец: «если указанное имя скилла уже есть, значит добавляемый URL надо
внедрить в существующий скилл органично, предупредив» + «если галочка снята — то
замещение. Но это опасная зона, надо всегда спрашивать: ты уверен?». Реализовано
в `tools/api.py` (ядро, без LLM) — три режима вместо прежнего «force».

- **Режим — следствие состояния, а не галочки.** Имя занято → долив; имя свободно →
  новый скилл. `mode=auto` решает это в ядре: `target` есть → `append`, нет → `create`.
- **`append` (долив, по умолчанию):** файлы, которых в цели нет, копируются; файлы,
  которые есть и **отличаются**, копируются только при `allow_overwrite=True`;
  то, чего нет в черновике, **остаётся как было** (в плане это `keep`).
- **`replace` (замена, «опасная зона»):** сначала **бэкап** всего каталога в
  `backups/<имя>-<ГГГГММДД-ЧЧММСС>`, только затем `rmtree` + копирование черновика.
  Иначе, как было раньше с `copytree(dirs_exist_ok=True)`, старые главы оставались
  при новом индексе в SKILL.md — то есть «замена» не заменяла.
- **Бэкап уникален по секунде.** Две правки подряд в одну секунду давали один
  каталог (наложение копий) — теперь к имени добавляется `-2`, `-3`. Держим
  последние `BACKUP_KEEP = 5` на скилл, старое вычищается.
- **Без `confirm` ничего не пишется.** `do_install` возвращает **план**:
  `added` / `overwrite` / `same` / `keep` + `mode` + `risk` + `warning` — это то,
  что панель показывает перед вторым кликом. LLM пишет только с нашего согласия.

**Проверено живьём (песочница `HERMES_HOME=D:/tmp/b2s-fakehome`, черновик `_probe`):**
план `create` → установка (15 файлов) → долив (новая глава + правка SKILL.md:
`added=1, overwrite=1, keep=1`) → `--no-overwrite` (SKILL.md не тронут) → `replace`
(старая глава снесена, в бэкапе она есть) → `auto` на существующей цели даёт
`append`, не `create`. Регресс-прогон после правок — зелёный.

**Журнал источников: долив помнит, что уже внесено.** `metadata.json` скилла несёт
`sources[]` (url/путь, заголовок, стратегия, объём, `first_installed_at`,
`last_installed_at`, `installs`) и `install_log[]` (последние 30 установок: режим,
добавлено/перезаписано/оставлено, путь бэкапа). Зачем: без этого вторая страница
вливается вслепую, и в скилле не остаётся следа, откуда взята та или иная глава.
План (dry-run) отдаёт `existing_sources`, и панель показывает «уже внесено
источников: N» **до** клика; после установки — строку журнала (новый источник или
обновлённый, сколько их всего и сколько раз ставили этот). `source` в корне
`metadata.json` остался как «последний источник» — скиллы, собранные раньше,
подхватываются как первый источник журнала.

Две ловушки, найденные тестом (`tools/tests/test_sources_journal.py` и
`tools/tests/test_install_modes.py` — оба лежат в форке и работают в песочнице `HERMES_HOME`,
профиль не трогая):

- **Снимок журнала обязан сниматься ДО копирования файлов.** Черновик приносит свой
  `metadata.json` и в режиме долива копирует его поверх целевого — история источников
  стиралась, `sources` не рос при каждом доливе. Теперь `prior = _read_json(target/metadata.json)`
  читается перед копированием, и поля `sources`/`install_log`/`source` берутся из него.
- **`auto` — не режим, а решение по состоянию цели.** Он нормализуется в `create`
  (цели нет) или `append` (цель есть) сразу при разборе запроса: иначе «auto» утекал
  в отчёт и в журнал установки, и по записи нельзя понять, что реально сделали.

Живой замер долива на реальном скилле (`productivity/rk7-sql-server`, временный
черновик, без `confirm`): `mode=append`, `target_exists=true`, план `added 14 /
overwrite 1 (SKILL.md)`, предупреждение «Долив в существующий скилл: добавится
файлов: 14; перезапишется: 1». `metadata.json` пока нет ни у одного скилла профиля —
журнал появится у тех, что собраны нашим пайплайном.

**Как перезапустить dashboard (новые REST-маршруты видны только после старта).**
Служба называется `HermesGateway (D:_NEURO_Hermes)` (nssm, работает от SYSTEM →
`sc stop` без прав даёт «Отказано в доступе»). Точечный рестарт ТОЛЬКО dashboard: `tools/restart_dashboard.bat` (форк; рабочая
копия — `D:/tmp/restart-b2s-dashboard.bat`) через
`powershell -NoProfile -Command "Start-Process -FilePath 'D:\tmp\restart-b2s-dashboard.bat' -Verb RunAs -Wait"`
(UAC подтверждает владелец). Чат это не рвёт: он живёт в отдельном процессе

`config.json` в синхронизации не участвует: он машинно-специфичный, его пишет

## Решения

- **Работаем только в своём форке**, апстрим не трогаем. Всё новое — **новыми
  файлами**, минимум хирургии в существующих: так обновления с апстрима остаются
  безболезненными.
- **Ветка `agent/url-dashboard`**, коммиты по частям: (1) загрузка URL + каскад
  стратегий как плагины, (2) staging/предпросмотр (черновик до установки),
  (3) дашборд-виджет в чате.
- **Каскад стратегий = мини-плагины на Python.** Три базовые: `raw-markdown`
  (если источник отдаёт `.md`), `html-cascade` (`trafilatura` → `bs4` → stdlib).
  Специфичные под конкретные странички — новые файлы `plugin_*.py`, подхватываются
  автоматически, ядро править не нужно.
- **Каждый плагин объявляет `matches(url) -> 0..1`** — порядок перебора по убыванию
  оценки, все попытки записываются в отчёт: видно, кто победил и почему. Это и есть
  механизм «перебирать, пока результат не станет лучшим».
- **Язык скилла — переключатель в виджете** (Русский по умолчанию / Английский /
  без изменений — как в источнике). Механика: **очищенный текст источника не переводится** —
  он всегда на языке оригинала (перевод стоил бы токенов и искажал бы цитаты, формулы, имена
  API). Язык применяется на этапе генерации: агент читает источник и пишет скилл на выбранном
  языке. Имена API, фреймворков и точные названия сущностей **остаются в оригинале** даже в
  русском скилле — иначе их не найти в документации; переводится проза, определения, пояснения.
- **`description` скилла — всегда английский** (`Use when <триггер>`, софт-лимит 60 символов из
  `validate_skill.py --lens hermes`): по нему Hermes выбирает, когда подгружать скилл, и он
  совпадает с общим рядом 60+ существующих скиллов. Русским делаем **тело** скилла.
- **Предпросмотр черновика — тумблер, выключен по умолчанию**, при включении модалка с честной
  ценой. Показ бесплатен; платится генерация, и **каждая перегенерация после правок — заново**
  (счёт растёт с числом итераций, а не «вдвое за один раз» — эту формулировку не повторять).
- **Панель — мастер из ПЯТИ блоков, а не простыня.** 1 источник → 2 анализ источника
  → 3 категория и имя скилла (реквизиты записи) → 4 черновик (без записи) → 5 запись
  в профиль. Открыт один
  блок (шапка сворачивает/разворачивает руками), главная кнопка — в правом нижнем
  углу футера («ДАЛЕЕ →», у блока 5 — кнопка записи), причина её неактивности стоит
  подписью рядом, а не молчанием. Переходы проверяются на месте и дёшево: 1→2
  источник не пуст; 2→3 есть отчёт о разборе **про этот** источник
  (`report.chars != null` и `fetchedSrc === src`); 3→4 имя скилла не пусто; 4→5
  черновик в staging. «ДАЛЕЕ» из блока 1 заодно запускает разбор: «идём дальше», а
  не «вернись и нажми».
  **Почему реквизиты записи стоят отдельным блоком 3, а не в хвосте мастера.** Владелец:
  «есть шанс, что мы собираемся доливать в готовый скилл» — а имя и категорию панель
  спрашивала уже на записи, то есть после генерации, когда долив/замена ещё не выбраны.
  Теперь блок 3 знает имя до черновика, блок 4 кладёт текст в известный каталог, а блок 5
  считает план как долив или замену. Единственный вход разбора — источник: имя и категорию
  в отпечаток входов разбора не пускаем (иначе «один чих в имени — и черновик заново»).
- **Источник «уже markdown» — блок 2 пропускается, и решает это панель, а не ядро.**
  Признак берётся из строки, без сети, до нажатия: `.md`/`.markdown` у локального
  пути или у `pathname` URL (query `?raw=1` и якорь `#...` не мешают). «ДАЛЕЕ» ведёт
  сразу в блок 3, шапка блока 2 подписана «Анализ MD файла — пропущен: файл уже
  markdown», метрики посмотреть можно (это бесплатно). Если ядро всё-таки вернуло
  HTML (стратегия не текстовая) — панель честно открывает блок 2.
  **`.txt` markdown НЕ считается** (владелец: «txt требует отдельного разбора — это
  далеко не md»): разметки заголовков в нём нет, главы ищет ядро, блок 2 нужен.
- **Шаг 1 (разбор источника) не уходит в чат при сбое ядра.** Тихий
  `sendIntent('rerun')` из catch снят: он выглядел как «отправил агенту», хотя шаг 1
  делает python, и счёт за LLM при этом рос. Теперь авария названа в строке статуса
  и получает «⟳ Повторить». Повторный вход гасит `busyRef` (двойной клик в один тик
  не копит REST), пока шаг в работе — action-кнопки заблокированы.
- **Текст блока называет ДЕЙСТВИЕ, а не номер чужого блока.** «Черновика нет — его
  пишет шаг 2» отправляло владельца в блок 2, который при готовом markdown пропущен:
  тупик без выхода. Теперь подпись говорит, где кнопка («черновик делает кнопка ✎ в
  этом блоке»), а номер блока называется только там, где он действительно нужен.
  Правило общее: ссылка на другой блок обязана нести путь туда, иначе лучше имя кнопки.
- **После платного шага, который делает агент в чате, панель следит за результатом
  сама.** `watchDraft()` читает `/draft` каждые 5 с (дедлайн 15 мин), по появлении
  файлов снимает ожидание, по дедлайну говорит честную ошибку; `draftWait` держит в
  шапке блока 3 «задание в чате — жду staging». Без этого «нажал и тишина» читается
  как поломка панели.
- **Разделяй черновик и установку.** Генерация идёт в staging, показ → правки →
  и только потом перенос в `$HERMES_HOME/skills/...`.
- **Ключ черновика ведёт ПОЛЕ источника, а не прошлый прогон ядра.** Панель
  спрашивает ключ у ядра (`POST /resolve {src}` - локально, без сети и без LLM) при
  вводе источника, а не берёт `draft_key` из `/state`: там ключ ПОСЛЕДНЕГО прогона, и
  после смены URL блок 3 показывал файлы прежней работы (владелец: «ввёл новый url -
  а в окнах содержимое предыдущей работы»). Смена ключа снимает сводку и текст
  черновика, план записи и статус установки: без снятия панель говорит про чужой
  источник. Вотчер держится за КЛЮЧ (не за имя) и читает источник через ref, иначе
  таймер продолжает жить со старым URL в замыкании.
- **Имя скилла панель ПРЕДЛАГАЕТ после разбора источника, а не при вводе URL.**
  В строке URL тема часто не названа (`.../186253740.html`), а в заголовке страницы
  названа; поэтому поле «Имя скилла» получает `suggested_name` из ответа `/rerun`
  (эвристика ядра `suggest_skill_name`), а `/resolve` отдаёт её же как догадку ДО
  разбора (панель ею не пользуется). Подстановка одноразовая: первая ручная правка
  поля закрывает её навсегда (`nameTouched`), под полем при этом сказано
  «подставлено по источнику - переписать можно тут же».
- **Загрузка не заменяет пайплайн апстрима.** Фетчер создаёт локальный `.md`/`.txt`,
  дальше работает неизменённый `scripts/extract.py` (метаданные, главы, SOURCE-маркеры).
- **Локальный источник — родным путём апстрима, а не через фетчер.** Каскад нужен
  только для сети: `resolve_input_files()` сетевых вызовов не делает, поэтому URL идёт
  в наш фетчер. Локальный путь фетчеру отдавать нельзя — именно так кнопка «Анализ
  источника» на `HERMES.md` давала «болт»: `raw-markdown` хватал любой `.md` и уходил
  в `urlopen` → `unknown url type: d`. Теперь путь берёт плагин `local-file`, и он
  **делегирует в `book_to_skill.utils.extract_single_file`**: определение формата —
  расширение (`SUPPORTED_EXTENSIONS`) + магия файла (`%PDF`, `PK` → `mimetype` /
  `word/document.xml`), парсер на формат, доставка недостающих экстракторов. Своё
  оставляем только там, где движок слабее: **не-utf8 кодировки** (цепочка апстрима
  `utf-8 → cp1252 → latin-1` не падает на cp1251, а молча отдаёт кракозябры — у нас
  cp1251/cp866) и **каталог** (склейка `.md`/`.txt` по алфавиту).
- **Чужой движок сначала изучаем, потом обвешиваем.** Прежде чем писать обёртку над
  book-to-skill — прочитать, что он уже умеет из-под капота (`config.py`,
  `utils.extract_single_file`, `dependencies.prepare_dependencies`, `cli.py`).
  Признак дублирования движка: своя таблица расширений, свой «detect format», второй
  реестр парсеров. На своей шкуре: свой читатель файлов пришлось переводить на родной
  экстрактор, потому что свой был хуже (без epub/docx/rtf/mobi) и уже.
- **Панель — штатный desktop-плагин Hermes** (`desktop-plugins/b2s/plugin.js` +
  REST `plugins/b2s/dashboard/plugin_api.py`), а не HTML-виджет: панель
  предпросмотра моста в чат не даёт (см. грабли), поэтому интерактив живёт в
  плагине — кнопки собирают интент и отправляют его в текущую сессию (RPC
  `prompt.submit`). `dashboard/widget.html` остался как автономный предпросмотр
  и отладка на своей машине.
- **Имя скилла и slug источника — разные вещи, и это разведено в UI.** «Имя скилла» —
  то, как скилл называется и лежит (`skills/<категория>/<имя>/`), поле редактируемое,
  по умолчанию подставляется эвристикой `suggest_skill_name()` из «сайт + тема»:
  `docs.python.org/3/library/pathlib.html` → `python-pathlib`,
  `learn.microsoft.com/.../csharp-13` → `microsoft-csharp-13`,
  `en.wikipedia.org/wiki/Kubernetes` → `wikipedia-kubernetes`. Приоритет источника
  имени: последний осмысленный сегмент URL → заголовок страницы → имя файла; если поле
  пустое, имя придумывает агент. «Slug источника» (`docs-python-org-3-library-pathlib-html`)
  — машинная метка сырья для имён скачанных файлов и каталога `staging/`, в поле только
  для чтения, в имя скилла не идёт. **Длина имени — три слова, не больше** (владелец:
  «слишком длинное название - максимум 3 слова»): имя работает триггером, по нему
  Hermes решает, подгружать скилл или нет, и `rkeeper-rekomendatsii-po-polucheniyu-
  spravochnik` в этой роли бесполезен. Сайт занимает одно слово, теме остаётся два;
  до отбора выбрасываются служебные слова (предлоги, артикли: `po`, `iz`, `how`, `to`)
  и длинные числовые хвосты (id страницы: `-186253740`). Из темы берутся ГОЛОВА и
  самое длинное из ОСТАЛЬНЫХ слов, когда тема вынута из слага: в слаге порядок слов -
  не фраза, и «два первых подряд» ловят прозу (`.../how-to-make-a-very-long-article`
  давал `make-very`, `rekomendatsii-po-polucheniyu-spravochnikov` - `po-polucheniyu`).
  Заголовок же - фраза, в нём порядок значим, поэтому оттуда берётся начало. Версия в
  теме не теряется: `csharp-13` остаётся `microsoft-csharp-13`. Живой пример:
  `docs.rkeeper.ru/.../rekomendatsii-po-polucheniyu-spravochnikov-iz-r_keeper-186253740.html`
  → `rkeeper-rekomendatsii-spravochnikov` (35 символов; прежнее поведение резалось по
  48 символам и давало имя в четыре с лишним слова).
- **Панель НЕ предзаполняет имя скилла.** Поле пустое (или подхватывает имя прошлого
  захода из `ctx.storage`), хардкод-пример вроде `python-pathlib` из `useState` убран:
  с ним человек ставил скилл под чужим именем, не заметив подстановки. Эвристика
  `suggest_skill_name()` остаётся в ядре (её зовёт агент), в поле она не пишется.
- **Пустое имя - незаполненный обязательный вход, и панель это ПОКАЗЫВАЕТ.** Поле
  подсвечено жёлтым (`WARN_YELLOW` = `#f59e0b`) и та же краска у подписи под ним -
  «имя скилла не может быть пустым!»; кнопка «ДАЛЕЕ» блока 1 погашена, причина в
  тултипе («нужно имя скилла: пустым не поставим»), а `next1` отдельно не пускает
  дальше, если имя стёрли после (защита от Enter и программного вызова). Подпись под
  полем - «такого скилла нет - будет создан новый» (полное слово, а не обрубок
  «будет новый»).
- **Рамку состояния берём ровно как у чипсы `DESCRIPTION.md`: `border: '1px solid ' +
  WARN_YELLOW`** — то же выражение, что в `catTone`. Ошибка была собрать «окантовку»
  из `borderColor` (ширина от темы) ПЛЮС `boxShadow: inset 0 0 0 1px`: на экране это
  двойная линия, и владелец справедливо сказал «беспредельно толстая». Цвет состояния
  и толщина должны совпадать с уже принятым в панели образцом, а не изобретаться:
  рядом с полем стоит эталон, на который смотрят глазами.
- **Дефолты виджета:** режим движка — `technical — таблицы и код`; галочка «Показывать
  предполагаемый скилл до записи» — **включена** (показ бесплатен), а цена генерации
  спрашивается модалкой в момент нажатия кнопки генерации/перегенерации (`askDraft()`),
  не при переключении тумблера.
- **Источник вводится полем, а не приходит из отчёта:** текстовая строка принимает и
  URL, и локальный путь (файл/папка); в конце строки — две **кнопки-ярлыка**
  (`Button size='icon-xs'` = 24×24, `shrink-0`; подписи «Выбрать файл» / «Вставить из
  буфера обмена» живут в `title` + `aria-label`). Ярлык — **цветной эмодзи** (`📂`/`📋`)
  с инлайном `fontSize: 13, lineHeight: 1, display: block`: монохромный SVG под
  `currentColor` владелец забраковал («ярлыки не цветные… раздражают»), а инлайн-кегль
  не даёт эмодзи плыть по базовой линии и раздувать строку (замер: глиф 13 px внутри
  кнопки 24 px, строка 28 px — ровно как у поля).
- **У обеих кнопок есть ШТАТНЫЕ двери приложения, и они предпочтительнее браузерных:**
  - **файл** берёт нативный диалог `window.hermesDesktop.selectPaths({ multiple: false,
    filters, title })` (IPC `hermes:selectPaths`) — отдаёт готовые ПОЛНЫЕ пути.
    `<input type=file>` + `getPathForFile` оставлены фоллбэком для сборки без этой двери;
    там браузер может вернуть только ИМЯ файла, и такое молча подставлять нельзя (ядро
    искало бы файл в cwd) — имя идёт в тост, а поле просит путь руками.
  - **буфер** читает `window.hermesDesktop.readClipboard()` (IPC `hermes:readClipboard` →
    `clipboard.readText()` в main-процессе), а `navigator.clipboard.readText()` оставлен
    фоллбэком. **Причина, по которой кнопка раньше молчала:** в Electron браузерное
    чтение буфера отказывает, когда документ не в фокусе — об этом прямо написано в
    `electron/main.ts` рядом с обработчиком `hermes:readClipboard`.
  Обе двери объявлены в `electron/preload.ts` (объект под `contextBridge.exposeInMainWorld`)
  и в `src/global.d.ts`; плагин исполняется в главном окне (blob-`import()` в
  `src/contrib/runtime-loader.ts`), поэтому `window.hermesDesktop` ему доступен.
  Отказ чтения, пустой буфер и отмена диалога **названы** тостом
  `host.notify({ kind, message, detail })` — молчаливых нажатий нет.
- **Схема интента виджета → агент (≤500 символов, лимит моста `::preview`):**
  `b2s <kind> | src=<URL или путь> | name=<имя скилла> | strat= | mode= | depth= | lang= |
  cat= | slug= | draft=0|1 | won= | junk= | model=`. Реальный замер на pathlib — **275
  символов**, запас есть. Ключ `src=` заменил прежний `url=` (поле источника теперь
  редактируемое), `name=` — имя скилла из UI. Отдельная ветка — **описание категории**:
  `b2s desc | cat=<категория> | dmode=write|fix | desc=<формулировка, необязательна>`.
  `write` — файла нет, `fix` — файл есть, но без frontmatter: ядро оборачивает прежний
  текст в шапку и **сохраняет его телом**, а не выбрасывает.
- **Действия в виджете — один нумерованный блок из трёх шагов, а не кнопки вразброс по
  полотну.** Шаг 1 «Прогнать источник заново» (`rerun`) — кнопка живёт **наверху, у поля
  источника**; только добыть и переизвлечь текст
  под выбранной стратегией и режимом, файлы скилла не пишутся, в постоянные скиллы ничего не
  уходит; шаг 2 «Сделать черновик» (`draft`) — платная генерация в `staging/`, и это **одна
  кнопка на первый заход и на переделку**: подпись меняется сама на «Перегенерировать с учётом
  замечаний», когда черновик уже есть (раньше тут стояли две кнопки с одной и той же командой
  `draft` и одинаковым интентом — владелец справедливо решил, что это одно и то же); шаг 3
  «Установить» (`install`) — перенос в `skills/<категория>/<имя>/`, кнопка гаснет, пока
  черновика нет. «Разобрать черновик» (`review`) живёт внутри блока черновика — это критика и
  список правок без перезаписи файлов.
- **Рабочий каталог убирается, но никогда молча.** Черновик живёт каталогом
  `staging/<слаг источника>`, сырьё — `b2s_fetched/<слаг>.*`. До этого захода их не
  удалял никто: после установки каталог оставался второй копией скилла навсегда, а
  сырьё копилось. Правила (выбраны владельцем):
  установленный черновик = **архив с TTL** (`STAGING_TTL_DAYS = 7` дней), свежие
  держим **лимитом** (`STAGING_KEEP = 5` сверх активного), служебные `_probe*` **не
  трогаем никогда** (на них стоят тесты ядра), и ни одно удаление не молчит — ядро
  называет, что уйдёт и почему (`reason`), а панель это печатает.
  Три двери: (1) **автоуборка при открытии панели** — `POST /prune {keep: 99, days: 0,
  apply: true}`, то есть ТОЛЬКО архив по TTL: лимит свежих в покое, потому что
  недоделанный черновик чужого источника убирать автоматически нельзя; (2) строка
  «рабочие каталоги в staging» в блоке 3 — список с числом файлов, пометкой
  «установлен», источником и **корзиной у каждой строки** (`POST /drop`); (3) кнопка
  «Убрать лишнее» — те же полные правила ядра (`POST /prune` без `keep`). Отметку
  «установлен» ставит установка в `metadata.json` самого черновика (`_mark_installed`),
  без неё уборка не отличит архив от незаконченной работы. Активный источник — тот,
  чей слаг совпадает с `src` **или** с `source.url` в metadata: каталоги, названные
  именем скилла (наследие), тоже защищены.
- **Реквизиты ЗАПИСИ живут в блоке 3, между разбором и черновиком.** «Категория скилла»
  (с описанием категории), «Имя скилла» и список скиллов категории стоят на своём шаге:
  это то, что нужно в момент генерации, а не разбора — блок 4 обязан знать имя и каталог,
  а блок 5 считает по имени долив или замену. Блок 1 теперь требует ровно
  один вход — источник. **Ядро обязано дописать `name:` в шапку `SKILL.md` при
  установке** (`_retitle_skill_md`, вызывается ДО копирования staging→target): имя
  выбирают после генерации черновика, а `name:` пишет LLM, и без подстановки каталог
  `skills/<категория>/<имя>/` разъезжается с шапкой — Hermes зовёт скилл чужим именем.
- **Служебный маркер авторства в `SKILL.md` — `creator` / `created` / `updated` внутри
  `metadata.hermes`.** Ставит ядро при установке (`_stamp_hermes_meta`, рядом с
  `_retitle_skill_md`, до копирования staging→target): `creator: BookToSkill`,
  `created` — когда скилл собран плагином, `updated` — когда последний раз перезалит.
  **`created` пишется один раз:** повторная установка его не перезаписывает, иначе «когда
  скилл появился» теряется; `updated` обновляется всегда. **Верхним уровнем эти ключи не
  кладём** — линза `hermes` считает их чужими и даёт 3 warning; внутри `metadata.hermes`
  — 0 warning (проверено на пробниках). **Контекст агента маркер не засоряет:** в
  системный промпт Hermes из шапки уходит только строка индекса
  `- {name}: {description}` (`agent/prompt_builder.py`, `available_skills` →
  `index_lines`), остальные ключи читаются лишь при `skill_view`. Плата за маркер — три
  строки в файле и ноль символов в промпте; выигрыш — по файлу видно, что скилл собран
  BookToSkill и когда. Владелец соглашался на маркер только при этом условии
  («если засоряет — не делать»), поэтому факт про промпт-билдер записан здесь.
- **Служебные файлы ядра в скилл не едут.** `merge-plan.json` — рабочая тетрадь ядра,
  в профиле ему делать нечего, а прежний `copytree` копировал каталог черновика целиком
  (владелец: «конечно json там не нужен в готовых скиллах»). Теперь `_SERVICE_FILES`
  фильтрует и план раскладки, и список записанных файлов, и само копирование
  (`ignore=`); в `staging` файл остаётся — панель его читает. Из трёх уже собранных
  скиллов профиля удалён.

## Грабли (проверено на себе)

- **Файл плагина проверяем РАЗБОРОМ ЦЕЛИКОМ, иначе вкладка молча исчезает.** В
  `nameNote` не хватило одной закрывающей `)` — Electron ответил
  `[plugins] runtime load failed (b2s) SyntaxError: Unexpected identifier 'useEffect'`,
  и вкладка плагина просто пропала из приложения, без единого сообщения в UI. При
  этом ВЕСЬ набор тестов панели был зелёным: они вырезают из `plugin.js` отдельный
  фрагмент и исполняют его через `new Function(...)`, поэтому невалидная часть файла
  в проверку не попадала. Правило: каждый JS-файл плагина отдаём node целиком
  (`node --input-type=module --check < plugin.js`) — это `tools/tests/test_plugin_syntax.py`
  (5 проверок). Признак аварии задним числом: строка `runtime load failed (<id>)` в
  `data/hermes/logs/desktop.log`. После правки плагина панель оживает на следующем
  старте Desktop: загрузчик плагинов срабатывает при запуске окна.
- **«Проверка не прошла» — не то же самое, что «не записали»: ядро пишет файлы ДО
  проверки.** `do_install` копирует staging→target и только потом зовёт
  `_validate`/`scan`, а `ok` считает по их результату. Поэтому `ok: false` с
  записанным скиллом означает «запись состоялась, а линза нашла замечания» -
  панель обязана назвать ОБА факта и напечатать сами замечания текстом
  (`installIssues`), а не «см. подробности ниже», которых она не показывала. Кнопка
  записи гаснет по факту записи (`dry_run === false || out.installed`), а не по
  `ok`: иначе на уже установленном скилле горит «Установить», и второй клик уходит
  в долив поверх него. Живой случай: имя `license-Info`, каталог появился, линза -
  `must be lowercase`, панель молчала про причину и не поменяла кнопку.
- **Имя, которое линза Hermes не примет, — такой же незаполненный обязательный
  вход, как пустое.** Регексп `^[a-z0-9][a-z0-9._-]*$`: заглавные, пробелы и
  кириллицу Hermes не берёт, а шапку `name:` пишет ядро при установке ИЗ ПОЛЯ
  ПАНЕЛИ, то есть ошибка вылезала ПОСЛЕ записи. Панель теперь ловит это до записи:
  жёлтая рамка, подпись с правилом, погашенные «ДАЛЕЕ» блока 3 и «Установить».
- **Тест не берёт фикстуру из живого `staging/`.** Уборка (TTL/лимит) сносит
  черновики прошлых прогонов, и `test_install_modes.py` падал
  `FileNotFoundError: staging\python-pathlib` на ровном месте. Песочницу тест
  собирает сам: SKILL.md с шапкой + `chapters/ch01..ch09` + глоссарий.

- **Правка шапки ПОСЛЕ копирования = правка в никуда.** `_retitle_skill_md` сперва
  стоял рядом с `_validate`, то есть после `shutil.copytree(staging, target)`:
  исправленный `name:` оставался в staging, а в профиль уезжала старая шапка.
  Признак ошибки: ядро отвечает `retitled: {changed: true}`, а в
  `skills/<кат>/<имя>/SKILL.md` по-прежнему чужое имя. Правило общее: всё, что
  ГОТОВИТ staging к записи, делается до копирования; после копирования пишут уже в
  цель.
- **Автоуборка не имеет права трогать свежий черновик.** `POST /prune` с дефолтным
  лимитом удалил бы и свежие чужие черновики — то есть недоделанную работу над
  другим источником. Поэтому панель при открытии зовёт `keep: 99` (архив по TTL), а
  лимит свежих остаётся ручным («Убрать лишнее»). Признак ошибки: после открытия
  панели исчез черновик, над которым никто не заканчивал. Проверяется тестом
  `test_pane_cleanup.py` («автоуборка: только архив (keep 99, срок ядра, apply)»).
- **TTL установленного черновика считается от УСТАНОВКИ, а не от mtime файлов.**
  Иначе архив, к которому случайно прикоснулись, живёт вечно. И «активный каталог»
  опознаётся по источнику (`src` / `source.url` в metadata), а не по имени каталога:
  каталоги, названные именем скилла, — наследие, и уборка не должна съесть тот, над
  которым человек работает прямо сейчас.

- **Черновик нельзя ключевать по имени скилла.** Пока каталог staging назывался именем,
  правка «Имя скилла» в блоке 1 уводила поиск в другой каталог, и панель показывала
  «черновика нет» на живом черновике — файлы целы, но панель их не видит (владелец:
  «обнаружил косяк - при изменении "Имя скилла" он сбрасывает в блоке 3 уже написанный
  LLM черновик»). Ключ = слаг ИСТОЧНИКА, имя — цель записи; каталог staging, названный
  так же, как имя скилла, — признак этой ошибки.
- **`_draft_dirs()` намеренно прячет служебные каталоги (`_probe*`), и поиск черновика
  не может ходить только через него.** План и установка обязаны сначала проверять прямой
  путь (`STAGING/<ключ>`, `STAGING/<имя>`): ядровые тесты работают на песочницах
  `staging/_probe*`, и без прямого пути они падают «черновика «_probe» в staging нет»
  при живом каталоге.
- **Ключ черновика берём ТОЛЬКО из явного `src`, не из состояния последнего прогона.**
  Иначе `do_draft('чужое-имя')` без источника находил по `metadata.json` черновик
  последнего разбора и подставлял его — ровно то, от чего страхует «чужое имя не
  подменяется свежим черновиком».

- **Формат staging-черновика диктует ядро, а не удобство автора.** Три проверки, которые
  молча врут о качестве: `validate_skill.py` принимает **файл** `SKILL.md` — на каталоге
  падает `PermissionError: [Errno 13]` (звать `--lens hermes staging/<имя>/SKILL.md`);
  `glossary_terms` в `/draft` считаются по строкам, начинающимся с `**`, — глоссарий
  таблицей даёт **0 терминов** при живом файле; security-скан ругается
  `tool.exfiltration_shape` на строку, где вместе есть `https://` (или
  `curl|wget|send|post|upload|transmit`) и слово из набора `.env|base64|secrets|credentials|api key`.
  Прежде чем считать находку реальной, проверить наличие ОБЕИХ половин правила:
  «записи в Windows Credential Manager … `https://github.com`» — ложное срабатывание,
  лечится переформулировкой (хранилище учётных данных Windows, узел без схемы).

- **`:8090` — это НЕ Hermes.** На этом порту сидит чужое приложение (llama.cpp Windows
  Manager: `{"app": "llama.cpp Windows Manager", "auth": "required"}`), а dashboard
  Desktop слушает динамический порт (`hermes serve --port 0`, свой PID), и basic_auth из
  `config.yaml` ему не подходит (401). Вывод: «постучать в REST панели» из терминала не
  выйдет — ядро проверять python-путём (`tools/api.py`, тесты `test_pane_*`), а сам REST —
  в живом окне плагина. Признак подмены: 401 на `/api/plugins/b2s/*` при живом `GET /`.

- **`git push` из этой оболочки: `git credential fill` ВИСНЕТ (таймаут), а
  `git-credential-manager.exe get` без username отвечает «Cannot prompt because user
  interactivity has been disabled».** Записи в Windows Credential Manager при этом
  есть (`git:https://github.com`, `gh:github.com:MRafStudio`). Рабочий вызов — с
  явным username и запретом интерактива:
  `printf 'protocol=https\nhost=github.com\nusername=MRafStudio\n\n' | GCM_INTERACTIVE=never "/c/Program Files/Git/mingw64/bin/git-credential-manager.exe" get`
  → отдаёт `password=…`, дальше push адресом `https://MRafStudio:$TOK@github.com/…`.
  Пушить только с `GIT_TERMINAL_PROMPT=0`: без него снова уйдёт в askpass и повиснет.
- **Тесты панели ловят смену раскладки — это их работа, а не помеха.** Проверки
  «статус в дереве раньше блока разбора» искали маркеры старой простыни
  (`s.kind === 'rerun' ? statusLine : null`); после переезда в блоки их надо
  перенацелить на новую разметку (`      statusLine,`, `        n: 2,`), а не удалять.

- **`trafilatura` с `include_formatting=False` молча убивает структуру.** При
   `output_format="markdown"` заголовки исчезают: замер на docs.python.org дал
   **22 заголовка → 0**. Для пайплайна это смертельно — детектор глав ничего не
   найдёт и скилл выйдет простыней. Всегда `include_formatting=True` + markdown.
   Проверять одной строкой: `grep -c '^#' b2s_fetched/<файл>.md`.
- **`trafilatura` 2.2.0 теряет ХВОСТ больших страниц.** Замер на pathlib (docs.python.org):
  HTML 266 554 Б → markdown 55 938 символов, обрыв на середине последнего раздела
  (`## Protocols`, метод `exists(`); bs4 на той же странице даёт 66 167 символов.
  Не лечится ничем из настроек: `deduplicate=False`, `favor_recall=True`,
  `MAX_REPETITIONS=1000`, `MAX_TREE_SIZE=1M`, `EXTRACTION_TIMEOUT=600` (весь разбор — 0.2 с,
  то есть не таймаут), подача только `div[role=main]` (50 953 симв, тот же обрыв), смена
  `output_format`. Вывод: «мусор 0» ≠ «текст полный» — полноту мерить отдельно, сравнением с
  bs4-объёмом. План: поле `coverage` в отчёте фетчера + предупреждение в CLI.
- **Подтверждено практикой (pathlib): потеря хвоста съедает целые таблицы, и вторая
  стратегия их возвращает.** В `.md` (trafilatura) пропала таблица `Corresponding tools`
  (31 соответствие `os`/`os.path` → pathlib + 4 сноски) — после вводной фразы сразу
  «Footnotes». В `.txt` той же страницы (стратегия `stdlib-html-parser`) таблица цела →
  взята оттуда в `cheatsheet.md`, а глава 9 честно помечает, откуда добор. Вывод: каскад
  стратегий — не теория, а рабочий ход; фетчеру нужен **добор хвоста вторым извлечением**
  при расхождении объёмов, а не только проверка на мусор.
- **Русская локаль переводит вывод `sc`, и разбор по маркерам врёт молча.**

       «Критика и список правок» была жива при пустом staging: задание уходило агенту, счёт за
       LLM рос, а ответом было «критиковать нечего». Теперь `disabled: !!busy || !hasDraft`,
       и причина не молчит (тултип `TIP.reviewOff` + подпись под рядом: «Критика включится, когда
       в staging появится черновик»). Правило общее: у кнопки, чей шаг требует артефакта, состояние
       = «артефакт есть», а причина неактивности названа словом, а не тишиной.

   21. **Кнопка обязана называть ДЕЙСТВИЕ ПЕРВОГО клика, а не конечную цель.** В блоке 4 стояла
       «Установить», хотя первый клик ничего не пишет (собирает план), и это было обманом: владелец
       прочёл подпись и решил, что запись пойдёт сразу. Решение — подпись меняется по состоянию:
       без плана «Предпросмотр», после плана «Установить», у режима замены своя («Подтвердить
       ЗАМЕНУ» — там сносится каталог). Правило: у двухшаговой кнопки слово на ней описывает
       шаг, который случится СЕЙЧАС; второй шаг — после того, как первый отработал.

   22. **Flex-колонка с потолком СПЛЮЩИВАЕТ содержимое вместо прокрутки, и `scrollHeight`
       врёт об этом.** Замер стендом (12 строк-подписей в зоне с `max-height: 7em`,
       `overflow-y: auto`): каждая строка сжалась до **2.5 px**, при этом `scrollHeight ==
       clientHeight`, то есть окно сообщало «переполнения нет», а текст был нечитаем.
       Причина: у flex-ребёнка с `overflow: hidden` (а это любая подпись под обрезку)
       автоматический минимум = 0, поэтому `flex-shrink` режет детей, и до скролла дело
       не доходит. Та же зона, но `display: block`: строки 16 px, `scrollHeight` 200 против
       82 — скролл честный. Поэтому все «окна» с потолком — БЛОЧНЫЕ (`ZONE_CAP`:
       `display: block` + `maxHeight: 288` + `resize: 'vertical'`, отступы держит
       `space-y-1`), а `flex` остаётся только у групп с прозой, где минимум защищён
       переносом текста. Грип и потолок живут в `ZONE_CAP` как ЕДИНЫЙ стандарт «окна»
       для блоков 3 и 4: показали пальцем на одно поле — получили их все (владелец:
       «добавить такие же Grip… и всё станет стандартизированным»). Новое окно панели
       берёт `ZONE_CAP`, а не собирает свой набор из `GROUP_CAP`. Проверять переполнение
       замером (`minKid`/`scrolls`), а не глазами: «скролл есть» и «строки не сплющены» —
       два разных вопроса.

   23. **План записи обесценивается любым действием в блоках 1–3 — и панель обязана это
       признать.** План построен по входам (источник, имя, категория, режим, черновик),
       поэтому `dropPreview()` стоит в `sendIntent`, `runRerun`, `runPlan`, `next1`,
       `loadText`, `loadDraftText` и в клике «обновить с диска»; плюс страховка-эффект на
       смену входов (`[src, name, cat, act, mode, lang, strat]`) — ловит правку полей
       клавиатурой, которую никакой кнопкой не отследишь. Поле предпросмотра при этом
       скрывается (план = `null`). **Исключение — тихий вотчер `loadDraft(silent)`:** он
       читает staging раз в 4 с и обязан НЕ стирать план, иначе собранный предпросмотр
       исчезал бы сам через несколько секунд. Владелец: «любое нажатие кнопок в блоках
       1,2,3 — должны сбрасывать флаг этой кнопки в блоке 4 и скрывать текстовое поле».

   24. **Список, склеенный в одну строку, не читается — единица списка живёт своей строкой,
       итоги — отдельно и вне прокрутки.** В блоке 4 план печатался как «＋ добавится (16): a,
       b, c …»: владелец видел «+ добавится (16): …» и не мог узнать, что ляжет в профиль —
       многоточие съедало список. Решение — структура окна блока 2: шапка и путь СНАРУЖИ («что
       за операция» и «куда пишем» прокручивать не нужно), внутри — прокручиваемое окно с фоном
       плагина (`PANEL_BG` + рамка `FIELD_LINE` + `data-glass-raised`, потолок 288 px как у поля
       текста, грип), в нём ПО СТРОКЕ НА ФАЙЛ со знаком действия (`＋`/`⟳`/`＝`), а под окном —
       сводка («добавится файлов: 16 · перезапишется: 2 · останется как есть: 3»), журнал
       источников, предупреждения и бэкап. Замер стендом: 21 строка по 13.5 px, `scrollH` 292
       против `clientH` 288, фон `rgb(18,18,21)`, итоги не уезжают под прокрутку. Правило общее:
       деталь, которую читают (файлы, главы, строки), — списком построчно; цифры и служебные
       пометки — сводкой; управление и итоги — вне скролл-зоны.

   25. **В выводимом тексте нет длинного тире — «—» читается как «написано ИИ».** Владелец:
       «в выводимом тексте (по всему плагину) надо заменить символы "—" на человеческие "-"».
       Правка сделана ОДНИМ проходом по строковым литералам (96 замен в `plugin.js`), а не
       поиском-заменой по файлу: 230 таких тире осталось в КОММЕНТАРИЯХ, и они никому не видны,
       а трогать их — только раздувать дифф. Тот же проход сделан по сообщениям ядра
       (`tools/api.py`, `tools/serve.py`) — их панель показывает теми же буквами, что и свои.
       Докстринги и комментарии Python не тронуты (обычные строки правились через `tokenize`,
       тройные кавычки отфильтрованы). Правило проверяет тест: он вырезает литералы `plugin.js`
       и валит сборку, если найдётся U+2014/U+2013 в выводимом тексте.

   26. **Подпись, которую владелец просит «на кнопку», переносится ЦЕЛИКОМ, а не дублируется.**
       В блоке 4 у кнопки стояли две подписи-состояния рядом («"Предпросмотр" соберёт план и
       ничего не запишет», «второй клик пишет в skills/…/»). Владелец: «выводить их подсказкой
       на кнопке, а не рядом с кнопкой». Теперь эти фразы — ровно `title` кнопки, меняющийся
       вместе с её подписью («Предпросмотр» → «Установить»), а `hint` у блока убран совсем.
       Полумера (оставить подпись и добавить тултип) дала бы дубль и тот же шум. Проверка:
       замер стендом — `title` у кнопки равен фразе, подписей рядом нет (`hint:` в блоке 4 не
       встречается).

   27. **Нативный `<datalist>` в панели не годится: он не знает контекста и его попап не
       прокрутить.** «Имя скилла» подсказывалось через `datalist` — и подсовывало ВСЕ скиллы
       профиля, хотя рядом выбрана категория (владелец: «выбрали категорию apple - значит в
       списке должны быть только те, кто входит в каталог apple, а не всё, что в принципе
       найдено на диске»), а длинный список не листался вовсе. Своя подсказка решает оба
       вопроса сразу: список строится функцией `skillsInCat(skills, cat)` (фильтр по категории,
       алфавит, пустая категория — пустой список), рисуется окном панели (`ZONE_CAP`: фон
       плагина, рамка поля, потолок 288 px, грип, скролл), а ввод имени остаётся свободным —
       `Input` никуда не делся. Перечитывается при открытии (`loadSkills()` + тумблер), как
       и всякий список, который читают с диска. Замер стендом: 27 скиллов в окне 288 px при
       `scrollH` 764 — листается; 2 скилла — окно по содержимому (84 px).

   ## Механика: панель, долив, установка (свод)

Детали и история — в `ЖУРНАЛ-АРХИВ.md`. Здесь то, без чего нельзя работать.

**Панель ничего не читает сама.** Виджет и плагин живут в песочнице (ни файловой
системы, ни сети) — это пульт: клик собирает интент (`b2s <kind> | src=… | name=… |
strat=… | mode=… | cat=… | draft=…`, ≤500 символов — лимит моста `::preview`) и
отправляет агенту, агент запускает фетчер или генерацию и перерисовывает панель.
Автозапуска по появлению URL нет и быть не может, поэтому шаг 1 подписан
«🔎 Анализ источника и очистка» с оговоркой «само ничего не происходит».
Три шага: 1) `rerun` — прогнать источник и почистить текст (файлы скилла не
пишутся); 2) `draft` — платная генерация черновика в `staging/`, и это одна кнопка
и на первый заход, и на переделку (подпись меняется сама); 3) `install` — перенос в
`skills/<категория>/<имя>/` (гаснет, пока черновика нет). `review` — разбор
черновика без записи файлов. Фидбэк кнопок живёт **наверху, у кнопки шага 1**, а не
под спойлером `#stage2`: иначе честное предупреждение показывается в закрытом
спойлере и клик выглядит как «ничего не происходит».

**Под выпадашкой категории — чипса с содержимым `DESCRIPTION.md`** (в своих границах,
чтобы текст не смешивался с полями), а не служебная подпись. Фон чипсе даётся **inline**
(`color-mix` от `BASE`), как блокам результата: классы на произвольных токенах панели
могут не доехать до её CSS; границы и текст берутся из `--ui-*` с запасными значениями.
Чипса рисуется **всегда**, когда категория выбрана: «ядро про неё промолчало» — это тоже
состояние (описания нет), а не повод оставить поле немым. У пустого каталога она добавляет
строку «каталог пока пуст».

**У блока описания состояние несут РАМКА и знак, а не заливка.** Подпись над блоком одна и без
прозы: «Содержимое DESCRIPTION.md» (служебные пояснения про промпт владелец потребовал убрать).
Фон блока — фон всего плагина (`PANEL_BG` + `data-glass-raised`, иначе стекло обнуляет токен в
transparent), потому что цветная вуаль спорила с зелёной кнопкой «починить» поверх неё — владелец
назвал это убогим, и верно: два цветных слоя на одной площади. Состояние читается рамкой, как
дорожный знак: **зелёная** (`--ui-diff-add-border`) — формат верный, Hermes описание видит;
**жёлтая** (`WARN_YELLOW`) — предупреждение: текст без frontmatter ИЛИ скиллы есть, а описания
категории нет; **красная** (`STOP_RED`) — файла нет у **пустой/новой** категории. Перепутать их
нельзя, и это не косметика: отсутствие `DESCRIPTION.md` у категории со скиллами — **не ошибка**.
Проверено по коду и живому промпту: Hermes индексирует скиллы по их `SKILL.md`, а описание
категории даёт ровно одну строку-подпись группы (`creative: <текст>` против `software-development:`),
и ни один скилл от отсутствия файла не пропадает. Поэтому красным красим только пустую/новую
категорию (там описание решает: скиллы положат наугад), а слов-пугалок («STOP») в блоке нет:
надпись читается человеком как поломка, которой нет. Кнопка в блоке — «Написать описание
категории», не «дописать»: файла-то нет, дописывать нечего.

**Подписи к объектам панели — одна строка и обрезка, никогда перенос.** Любая подпись объекта (путь,
URL, имя файла, строка плана и раскладки, подпись поля, шапка блока с данными) живёт в одну строку,
лишнее режется многоточием, полный текст уходит в `title` (читается наведением). Перенос такой
подписи распирает бокс и ломает раскладку блоков, боксов и кнопок. Замер стендом на реальном CSS
приложения: при ширинах 160–340 px один длинный путь давал 4 строки, шапка плана 3, подпись поля 2;
после фикса — ровно одна строка и обрезка. Приём — хелпер `Ell()` на верхнем уровне модуля
(`truncate` + `minWidth: 0` + `display: block` + `title`), для подписей в кнопках — обёртка `CHIP_FIT`
(`maxWidth: 100%`/`minWidth: 0`/`flexShrink: 1`). Многоточие требует блочного бокса: у flex-контейнера
(какова кнопка) его нет, поэтому подпись всегда лежит в своём `span`. Проза (сообщение об ошибке,
пояснение, сам извлечённый текст) переносится по-прежнему — там важна полнота.

**Значение комбобокса — тоже подпись объекта.** `SelectValue` из SDK — голый span от Radix, а
триггер собирается как `controlVariants()` + `whitespace-nowrap`: flex-элемент с `min-width: auto`
не сжимается ниже min-content, и значение вылезает за бокс триггера (замер на реальном CSS: +87 px
при панели 160 px, +3 px при 200 px). Правка — в потребителе, не в SDK: значение получает
`min-w-0 flex-1 truncate` и `title` с подписью выбранного варианта (в DOM у Radix лежит только
`value`, подпись достаётся из массива опций). Относится ко **всем** комбобоксам панели — баг у них
одинаковый.

**Рамки полей и комбобоксов панели делает приложение, и наша ручка — knob, а не инлайн-борт.** Борт
поля приложение рисует unlayered-правилом `.desktop-input-chrome`:
`color-mix(in srgb, var(--dt-composer-ring) var(--dt-input-border), transparent)`, где ring = `--ui-base`,
а knob в теме 7 % (светлая) / 4 % (тёмная) — в комментарии самих стилей это «invisible at rest». На стекле
панели такое поле читается как поле без рамки (владелец: «просто швах»). Лечится не рисованием борта, а
подъёмом knob: `style: { '--dt-input-border': '22%' }` на **корне панели** — все `Input`/`SelectTrigger`
внутри наследуют, 22 % даёт ровно плотность борта поля артефакта, а hover (×2) и focus (полный ring)
приложение продолжает считать само. Инлайновый `borderColor` заморозил бы все три состояния разом:
инлайн бьёт unlayered-правила, и контрол умер бы на наведении и фокусе. Замер над тёмным стеклом
(rgb 22,22,24): knob 4 % → rgb(30,30,32), контраст 1.09:1; 22 % → rgb(68,68,70), 1.86:1.

**`Ell` — это props, а не элемент: в `children` его класть нельзя (панель не грузится).**
Хелпер обрезки `Ell(text)` возвращает объект пропсов `{className, style, title, children}`; чтобы
получить узел, есть `cutSpan`. Написав `children: Ell(...)`, получаешь React #31 «objects are not valid
as a React child (found: object with keys {className, style, title, children})»: панель уходит в
error-boundary и **не рисуется вообще** — симптом выглядит как «панель не грузится», а не как ошибка
хелпера. Проверено на строке статуса (шаг 1 панели b2s). `node --check` такое пропускает (синтаксис
чистый), вотчер панели тоже — ловушка ставится точечно: `grep -n "children: Ell(" plugin.js` должен
быть пуст, и эта же проверка живёт в `tools/tests/test_pane_head.py`. Если панель вдруг перестала
грузиться после правок — смотреть лог приложения (`hermes/logs/desktop.log`) на `React #31` прежде чем
перезапускать Hermes: правка `plugin.js` подхватывается хот-релоадом, перезагрузка приложения не нужна.

**Описание пустой категории в промпт не попадает — и это не поломка.** Индекс скиллов Hermes
строит по скиллам: группа появляется в нём вместе с первым `SKILL.md`, а категория с нулём
скиллов не даёт ни строки. Значит `DESCRIPTION.md`, написанный для пустого каталога (`networking`),
— **заготовка**: она ждёт первый скилл. Писать её всё равно осмысленно и лучше заранее: когда
скиллы начнут складывать, ориентир уже будет на месте, а не появится задним числом.

**Действие, ушедшее в чат, панель сама не отследит — нужен вотчер.** Описание категории
сочиняет LLM, поэтому клик уходит интентом в сессию, а панель про результат не узнаёт: файл
на диске появился, рамка блока осталась красной, кнопка «написать» — на месте. Владелец
сформулировал точно: «ты не сделал последний шаг — не перечитал текущую выбранную категорию».
Поэтому после интента `desc` / `desc-fix` панель запускает `watchDesc(cat, before)`: раз в
2.5 с читает `/categories`, сравнивает `desc_state` цели со снимком и, как только состояние
изменилось, перечитывает снимок ядра целиком (список, `details`, `loose`). Следим за **именем
цели**, а не за текущим выбором в выпадашке: пока агент думает, владелец вправе переключить
категорию, и обновить нужно именно ту, которую правили. Тупик тоже закрыт: три минуты без
изменений — панель честно говорит, что состояние не поменялось, и отправляет смотреть ответ
в чате, а не висит молча.
**Проверено живьём 2026-09-12:** файл описания грохнули руками → панель красная → клик по кнопке →
ядро записало → рамка позеленела сама, кнопка исчезла, ничего не переоткрывали.
Тест — `tools/tests/test_pane_watch.py` (14 проверок: вотчер вырезается из живого `plugin.js`
по балансу скобок и исполняется в node на моках ядра, без приложения и браузера).
Урок перенесён в скилл `hermes-desktop-html-previews` → `references/desktop-plugin-pane.md`.
Жёлтый и красный остаются константами плагина намеренно: warning и error не должны стать
неотличимыми в чужой палитре, где зелёный переопределён. Заливка 12% осталась только у блока
«Результат разбора» — там состояния нет, и вуаль ни с чем не спорит.

**Кнопки-действия внутри блоков: нейтральные — фоном обёртки, лечащие — зелёным токеном темы.**
Помощник один — `chipAction(label, onClick, disabled, tone)`, и фон всегда навешен на обёртку
`div` с `data-glass-raised`, а не на саму кнопку: inline-фон убил бы hover ghost-варианта.
Нейтральный тон («показать весь текст», «Разобрать черновик») — `PANEL_BG`
(`--ui-chat-surface-background` → `--ui-bg-chrome`). Тон `fix` («Починить файл», «Дописать
описание категории») — зелёный **из темы, без своих hex**: заливка
`color-mix(in srgb, var(--ui-green) 20%, transparent)`, рамка `--ui-diff-add-border`, текст

Ищи токены в теме приложения — `apps/desktop/src/styles.css`, там же `--ui-red`, `--ui-yellow`.

**Список категорий — это каталоги на диске, а не только те, где уже лежит скилл.**
Пустой каталог верхнего уровня (`networking`) — такая же категория: папка есть, значит её
должно быть видно и можно выбрать, иначе скилл в неё заводится только набором имени руками.
В выпадашке пустые помечаются `(пусто)`. Вложенные каталоги берутся **только** по
`DESCRIPTION.md` или по скиллам внутри — иначе служебные подпапки скиллов (`references`,
`assets`, `scripts`) вылезают в списке категорий. Признак «в каталоге ни одного SKILL.md» —
`details.<cat>.empty`.

**Категория = каталог, в котором `SKILL.md` лежит прямо** (`skills/<X>/SKILL.md`).
Hermes считает её категорией `<X>`, а скилл носит то же имя
(`prompt_builder._build_snapshot_entry`: при двух сегментах пути `category = parts[0]`),
поэтому в выпадашке она обязана быть. В `loose` уходит только `SKILL.md` прямо в
`skills/` — Hermes кладёт такой файл в служебную `general`, выбирать нечего. Раньше ядро
сбрасывало в `loose` все односегментные каталоги, и пять живых категорий
(`cpp-build-toolchain`, `dotnet-http-server`, `hermes-token-saving`,
`terminal-server-patterns`, `windows-per-app-proxy`) в панели не появлялись вовсе —
хотя на диске были и в промпте агента шли категориями. Правило сверять так:
`python tools/api.py categories` → `count` и `loose` (у живого профиля ожидаем `loose: []`),
живой маршрут — `python tools/probe_route.py categories`.

`loose` (SKILL.md прямо в `skills/`) — это **не** категории, выбрать их нельзя, и в панели
они больше не показываются: строка висела под чипсой и пугала зря — под неё попадали
нормальные односегментные категории (см. выше). Данные остаются в ответе ядра (`loose`),
UI молчит.

**Список категорий панель перечитывает при КАЖДОМ открытии выпадашки, а не один раз при
монтировании.** Причина — Fast Refresh: при хот-релоаде `plugin.js` React **сохраняет состояние**
компонента, поэтому единожды прочитанный список = профиль на момент открытия панели. Так и
терялась `networking` (каталог на диске есть, `/categories` его отдаёт, а в списке нет, пока
панель не переоткроют) — и это выглядело как «чинили категории третий раз по кругу», хотя ядро
и UI были правы. Правило: любой список, который читается с диска (категории, скиллы), обязан
иметь функцию-загрузчик (`loadCats` / `loadSkills`) и вызываться повторно — при открытии списка
(`onOpenChange`) и сразу после записи (установка). Проверять так: правки **рендера** видны сразу,
а правки **данных** — нет; значит дело в сохранённом состоянии, а не в коде ядра.

**Долив и замена.** Имя скилла = имя папки, без дублей: занятое имя → режим `auto`
разрешается в `append` (цели нет → `create`), и в отчёт с журналом пишется
**конкретный** режим, а не `auto`. Перед записью панель показывает **план** (сколько
файлов добавится и перезапишется, какие источники уже в журнале) — запись только
после подтверждения и с бэкапом (`backups/`, `BACKUP_KEEP=5`, уникальный label;
предыдущая версия черновика → `staging/<name>.prev-<date>/`). `metadata.json.sources[]`
— журнал источников: при доливе он **мержится** с прежним (снимок читается ДО
копирования файлов, иначе история затирается), там же `install_log` и `source`.
Категория — **из существующих в профиле или своя, набранная в поле** (пункт
«✎ своя категория…» внизу списка): своя папка создаётся при установке, но тогда ей
**обязательно нужно описание** — иначе Hermes покажет категорию агенту голым именем.
Вложенность разрешена (`mlops/evaluation`), каждый сегмент проверяется отдельно:
`..`, точка и `_` в начале отсекаются, поэтому `../evil` до диска не доходит.

**Описание категории — это её описание в промпте агента, а не подпись в UI.**
`DESCRIPTION.md` читает сам Hermes (`agent/prompt_builder.py:_read_category_descriptions`)
и вставляет `description` рядом с именем категории в индекс скиллов. Отсюда правило
панели: под выпадашкой показывается **содержимое файла**, а не служебный текст
(«только существующие — 17»). Три состояния вместо галочки «файл есть»: `ok` — текст
в чипсе; `no-frontmatter` — текст есть, но Hermes его не читает (нужен frontmatter) —
треугольник + кнопка «починить файл»; `no-file` — треугольника + «дописать описание».
Состояние отдаёт `GET /categories` (`details`), кнопки — интентом `desc`, файл пишет
ядро (`tools/api.py desc`), а формулировку даёт агент или человек из того же поля.

**План по главам при доливе: Python считает карту, решает LLM.** Файловый план
отвечает «какие файлы лягут», но не «что слить со старыми главами, а что писать
заново». Перед записью ядро строит **раскладку**: для каждого `.md` черновика
ищет ближайшие файлы скилла ТОГО ЖЕ типа (глава к главе, глоссарий к глоссарию)
по словарю значимых слов и заголовкам и выносит `add` / `merge` (`merge_into` +
близость) / `rewrite` (тот же путь). Решение остаётся за LLM: Python даёт карту и
числа, не приговор. Файлы-цели слияния **не** попадают в «остаётся как есть» —
они идут списком `touched` («будет дополнен»), иначе план врёт. Готовый блок
`prompt` + раскладка ложатся в `staging/<имя>/merge-plan.json`, агент читает его
файлом. Наружу это `POST /api/plugins/b2s/plan` (`python tools/api.py plan
--name …`) и кнопка «3′. План по главам» под шагом установки; в ответе `counts` и
`confidence` («high» — пересечение сильное, «medium» — смотреть глазами).

  начинать с замера кегля и `line-height`, а не с `align-items`: лечится единым кеглем и
  цветовым токеном (`text-xs text-(--ui-text-primary)`), а не выравниванием. Тот же ряд

  честно; в **колонке** (`flex flex-col`) `align-items: stretch` тянет её на всю ширину
  панели, и владелец видит зелёную полосу, активную только под надписью («фон вытянут на

  364–368 против кнопки 297 — дырка ~70 px. Лечение: `alignSelf: 'flex-start'` +
  `maxWidth: '100%'` на обёртке → фон 297 = кнопка 297, а на 200/250 px кнопка попрежнему
  сжимается и режет текст. Наивные `self-start`/`w-fit` **без** `max-width` дают другое
  зло: на 200/250 px кнопка перестаёт сжиматься и уезжает за рейл (outRail 109/59 px).
  Фон ставится обёртке, а не кнопке: у `ghost` inline-фон убил бы hover — поэтому фикс
  живёт на обёртке. Родителя менять нельзя, не проверив: у кнопок шага 1 и «Сделать
  черновик» родитель — тот самый ряд, дыры там нет (замер: разница 0 на 200/250/380).

## Грабли (проверено на себе)

- **Плашку режима нельзя вешать на факт отправки задания.** `busy` панели снимается через миллисекунды после `prompt.submit`, а LLM думает минутами: всё это время шапка показывала зелёное «прямой режим · локальный Python» - то есть врала, что работы нет (владелец: «должно было переключиться на жёлтый "в работе LLM"»). Честный сигнал - занятость сессии: `host.state.busyBySession` (тот же пульс, что в статусбаре), плюс незавершённый черновик (`writing`). Ветка «в работе LLM» обязана стоять в шапке ПЕРВОЙ, выше «работаю» и «прямой режим», иначе жёлтое не покажется никогда. Сторож - `test_pane_mode_badge.py`.
- **Дедлайн вотчера считай от ХУДШЕГО случая, а не от среднего.** 15 минут не хватало на крупный PDF, где агент ещё и долго думает над планом: панель сдавалась раньше LLM. Поставлено 30 минут; при этом единственный признак завершения - маркер готовности, дедлайн лишь снимает ожидание.
- **Готовность черновика объявляет LLM, а не панель по каталогу.** «Каталог в staging найден» ≠ «черновик написан»: агент пишет файлы по одному, и панель, считавшая готовностью первый же файл, открывала «ДАЛЕЕ» блока 4 и запись в профиль на середине работы - скилл уезжал обрезанным (владелец: «прыткий пользователь перейдёт к блоку 5 и запишет обрезанный скилл»). Контракт: агент последним шагом кладёт в каталог черновика `READY.json` (`python tools/api.py mark-ready --src <url>`), ядро отдаёт `ready`/`writing` в `do_draft`, панель запирает «ДАЛЕЕ», «Критику» и «Предпросмотр» на `ready` (запись - ещё и на пройденный блок 4), а `do_install` отказывает без маркера. Маркер в `_SERVICE_FILES`: в профиль не едет и в счёт файлов не входит. Снял маркер (`--no`) - черновик снова «пишется».
- **Тесты-фикстуры тоже надо помечать готовыми.** Обновив контракт, не забудь про `tools/tests/`: фикстуры без `READY.json` падают на защите (и это правильно) - падали `test_install_modes`, `test_category_desc`, `test_retitle`, `test_sources_journal`. Сторожа панели - текстовые: они держат старые подстроки (`disabled: … || !hasDraft`), их надо править вместе с кодом, иначе регресс покажет не то место.
- **Большой текст одним вызовом приходит усечённым.** `write_file` с несколькими файлами в одном ответе и `patch` с длинным `new_string` иногда записывают обрывок - в файле оказывается буквальный `...[truncated]`. Пиши файлы ПО ОДНОМУ за вызов и после каждого сверяй размер и хвост (`wc -c`, чтение конца): приёмка «написано» от инструмента об усечении не говорит.
- **Сырьё черновика может исчезнуть до сверки имён.** `b2s_fetched/<слаг>.md` убирается ядром вместе с каталогом черновика (`do_prune_staging` сносит и то, и другое) - к моменту, когда руки дошли до `grep` по источнику, файла может уже не быть (так ушло сырьё пяти черновиков сразу). Сверку имён делай ПОКА сырьё на месте; утраченное восстанавливай штатным `python tools/api.py rerun --src <url>`, а не памятью.
- **`chars` в `report.json` - символы, а не байты файла.** Русский текст в UTF-8 даёт примерно вдвое больше байт: `ls` показывал 3 430, а `chars` - 2 346. В `metadata` и `coverage_note` пиши `chars`/`words` из отчёта, размер файла там неуместен.
- **Страница-каркас: главы режет команда, а не заголовок.** Источник может быть крошечным (717 символов, `headings: 0`) и содержать только два запроса с нулевыми значениями (`guid=""`, `id="0"`, `lockguid=""`). Тогда: главы - по командам (пауза, возобновление), нулевые значения назвать каркасом, а ответы и коды ошибок не выдумывать (в источнике их нет). Расшифровка одного поля дословно («детализация тарификации») - это всё, что даёт источник, и расширять её нельзя.
- **Производные данные живут вместе с источником, а не сами по себе.** «План по главам» построен по тексту ПРЕЖНЕГО черновика, поэтому сниматься он должен там же, где снимается черновик (сменился ключ источника - сброс; нажата «Сгенерировать черновик» - сброс). Иначе в спойлере висят строки чужого разбора, и виноватым выглядит новый источник (владелец: «висит со старыми записями, даже при нажатии Сгенерировать черновик»). Правило: у каждого поля с производными данными найди ВСЕ места, где сбрасывается то, из чего оно выведено, и добавь сброс туда же; сторож считает вызовы (`src.count(...) >= 2`).
- **Состояние в заголовке шага - по ФАКТУ шага, а не по виду входа.** Блок 1 запускает разбор своим «ДАЛЕЕ», но заголовок продолжал говорить «URL - нужен разбор» и после успешного анализа (владелец: «когда анализ завершён, можно менять состояние на "анализ завершён"»). У шага должно быть четыре состояния: пусто, работа идёт, завершено, авария - и цвет им (null/working/done/bad) обязан идти следом, иначе зелёный/красный врёт.
- **Инструмент, привязанный к режиму записи, показывай только в этом режиме.** «План по главам» считает пересечение тем с главами УЖЕ СТОЯЩЕГО скилла - то есть существует только для долива. Пока имя свободно, пересекать не с чем, и кнопка с подписью и спойлером врала о своей пользе (владелец: «показывать только если в группе 3 выясняется, что скилл уже стоит»). Признак режима уже есть в панели (`existing`), его и надо спрашивать. - **MSYS-путь `/d/...` не транслируется python:** `--out /d/...` дал каталог `D:\d\...`.

- **Утверждения исполнителей проверяй по первоисточнику:** grep по обоим извлечениям.

- **Тест не берёт фикстуру из `staging/`:** уборка сносит черновики (`FileNotFoundError`).

- **`browser_exec` не работает** (CDP запрещён с Chromium >=136): свой headless Chrome `chrome_cdp.py`.

## Решения (вынесено из HERMES.md 2026-09-15)

- **Свой форк, апстрим не трогаем; новое - новыми файлами** (апстрим-обновления безболезненны).
- **Каскад стратегий - мини-плагины Python**: базовые `raw-markdown` (источник отдаёт `.md`) и `html-cascade` (`trafilatura` -> `bs4` -> stdlib); специфичные - новые `plugin_*.py`, подхват автоматический.
- **Таблицы получают строку-разделитель постобработкой**: `fix_md_tables` в `plugins/generic.py` правит вывод `trafilatura` (блоки `|`-строк от 2 колонок без разделителя), в заметки отчёта идёт `tables: added markdown separator rows`. Без разделителя markdown таблицу не видит: в панели это простыня с палками, а глоссарий по таблице даёт 0 терминов. Уже корректную таблицу не трогаем.
- **`matches(url) -> 0..1`** у каждого плагина: перебор по убыванию оценки, все попытки в отчёт.
- **Язык - переключатель в панели** (Русский / Английский / без изменений): чистый текст источника не переводится, язык - при генерации, имена API в оригинале (дословно - архив).
- **`description` скилла всегда английский** (`Use when <триггер>`, софт-лимит 60, `validate_skill.py --lens hermes`); русским - тело.
- **Предпросмотр черновика - тумблер, выключен по умолчанию**; модалка с ценой при включении. Показ бесплатен, платится генерация; перегенерация после правок - заново.
- **Мастер из ПЯТИ блоков**: 1 источник -> 2 анализ -> 3 реквизиты записи (категория + имя) -> 4 черновик (без записи) -> 5 запись в профиль. Открыт один блок (шапка руками); кнопка - правый низ футера («ДАЛЕЕ ->», у блока 5 - запись), причина неактивности - подписью. Гейты: 1->2 источник не пуст; 2->3 отчёт **про этот** источник (`report.chars != null`, `fetchedSrc === src`); 3->4 имя не пусто; 4->5 черновик в staging; «ДАЛЕЕ» блока 1 запускает разбор.
- **Реквизиты записи стоят блоком 3, а не в хвосте**: блок 3 знает имя до черновика, блок 4 - каталог, блок 5 считает долив или замену; имя и категорию в отпечаток входов разбора не пускаем.
- **Источник «уже markdown» - блок 2 пропускается, решает панель**: признак из строки, без сети - `.md`/`.markdown` у пути или `pathname` URL (`?raw=1`, якорь не мешают); шапка блока 2 - «Анализ MD файла - пропущен: файл уже markdown»; ядро вернуло HTML - блок 2 открывается; **`.txt` markdown НЕ считается**.
- **Шаг 1 при сбое ядра не уходит в чат**: тихий `sendIntent('rerun')` из catch снят (падало 30-секундное задание и запускалось повторно); авария - строка статуса + «⟳ Повторить», повторный вход гасит `busyRef`; action-кнопки блокируются при `isRunning`.
- **Подпись называет ДЕЙСТВИЕ, а не номер чужого блока** («черновик делает кнопка ✎ в этом блоке»); ссылка на блок обязана нести путь туда, иначе - имя кнопки.
- **После платного шага панель следит сама**: `watchDraft()` читает `/draft` каждые 5 с (дедлайн 15 мин), файлы снимают ожидание; `draftWait` в шапке блока 3 - «задание в чате - жду staging».
- **Черновик отделён от установки**: генерация в staging, показ -> правки, перенос в `$HERMES_HOME/skills/...`.
- **Панель говорит про ПОЛЕ, а не про последний прогон ядра**: ключ черновика ведёт `POST /resolve {src}`, не `draft_key` из `/state`; смена ключа снимает сводку, черновик, план, статус установки; вотчер - за КЛЮЧ; спойлер «Результат разбора» - только у отчёта с текущих входов (`analyzed`), отпечаток входов панель берёт из `/state` у ОТЧЁТА (`report_inputs`), а не у поля ввода; имя и категорию в отпечаток не пускаем.
- **Красная граница - тому шагу, чей это дефицит**: ядро называет `failure_kind` (`source` - источник не получен; `strategy` - источник есть, не подошёл разбор; строка, не похожая на источник, - всегда `source`: «1» в поле не станет виной разбора). Панель краснит ровно один блок: при `source` - блок 1 словами «не удалось получить источник», при `strategy` - блок 2; авария REST-ядра не краснит никого (есть строка статуса). Владелец: «ввёл в поле "Источник" цифру 1. А получил - группу 2 "Анализ источника" с красной границей».
- **Зелёная граница блока 1 - у ДОСТУПНОГО источника, и это проба, а не разбор**: критерий шага 1 - «указанный в поле файл или url существует/доступен» (владелец, дословно). Панель спрашивает у ядра пробу (`serve.source_status` через `POST /probe`) при вводе, ДО разбора: путь проверяется на диске, URL - запросом (HEAD, при 403/405 - GET). Проба подтвердила - граница зелёная, даже если разбор ещё не делали; проба отказала - красная с причиной словами («файла нет по пути: …», «URL ответил HTTP 404 - источник недоступен», «не похоже ни на URL, ни на путь к файлу: 1»), и «ДАЛЕЕ» не открывается. Разбор тут ни при чём: `analyzed`, `report_inputs` и «отчёт снят с ЭТОГО источника» остаются признаком блока 2 - чтобы голая «1» не зеленела от чужого удачного отчёта. Владелец: «в группе 1 успешным является, если указанный в поле файл или url существует/доступен. В противном случае - провал».
- **Ввод, который источником быть не может, панель отвергает сразу - без похода в ядро**: форма источника видна из самой строки (`srcShape` в панели): `http://`, `https://`, `ftp://`, `ftps://`, `file://` - URL; `D:\...`, `/home/...`, `\\share`, `~/`, `./` - путь; всё прочее («3», «вчера», «42.md») - НЕ источник, и ответ даётся мгновенно, ещё до вызова `POST /probe`. Иначе «проверяю источник...» на «3» висело бы до ответа, которого не будет никогда (владелец: «что там его проверять? Он явно невалидный! Что, ждать какой то там таймаут которого никогда не произойдёт?… будет сидеть до утра и ждать»). Там же: молчащее ядро (маршрута `/probe` нет - модуль ядра грузится на старте) панель называет вслух (`kind: 'core'`, «ядро не ответило на пробу источника»), а не молчит вместе с ним. Схемы - по владельцу: ftp и ftps тоже URL (`serve.SRC_URL_SCHEMES`, `base.URL_PREFIXES`), причём ftps идёт своим путём через `ftplib.FTP_TLS` - urllib этой схемы не знает вовсе («unknown url type: ftps»); обёртка `@url:`...`` разворачивается (`_unwrap_src`).
- **Строка состояния помнит, про КАКОЙ ввод сказана.** После успешного разбора панель пишет «источник разобран: стратегия trafilatura…», и эта строка висела даже когда в поле ввели новое («1»): блок 1 честно говорил «не источник», а под плашкой оставалась работа прежнего источника. Владелец: «под плашкой надпись о том, что "источник разобран" так и осталась! Ну это же неправильно!» Причина: `status` - одна строка на всю панель и она не знала своего ввода (`fetchedSig` защищал от этого только зелёную границу, не текст). Теперь `say(text, sig)` запоминает отпечаток ввода рядом с текстом, а рендер показывает строку только пока `statusSig === curSig`; сообщения о черновике, раскладке по главам и записи идут через `saySrc` - тот же отпечаток. Сообщения не про источник (связь с ядром, уборка, аудит) остаются без привязки и живут сами.

- **Пропущенный шаг - это ПРОЙДЕННЫЙ шаг: у markdown-источника блок 2 зелёный.** Панель сама говорит «markdown: блок 2 пропустим», но граница блока 2 держалась на тоне `skip` (= `currentColor`, серый), а «ДАЛЕЕ» гасилась по `!analyzed` - шаг выглядел нетронутым и вёл в тупик, хотя работы у него не осталось (`block2Passed = analyzed || mdSrc`). Владелец: «раз пропустим, то почему тогда блок 2 не окрасился зелёным? Ведь напрашивается? Он же уже валидный?» Теперь тон - `done` (зелёный), кнопка доступна (`disabled: !!busy || !block2Passed`), а `next2` у md-источника идёт тем же путём, что «ДАЛЕЕ» блока 1 (`next1()`: снять метрики, обработать сбой) - метрики для черновика нужны, чистка нет. Почему шаг пропущен, по-прежнему сказано словами: в состоянии блока и в подсказке.


- **Шарик у заголовка и плашка рядом говорят об ОДНОМ - о связи с ядром**: было две оси у одной пары - шарик краснел от `tone === 'error'` (любая локальная ошибка шага), а плашка читала `core`; при живом ядре выходило «красный шарик + зелёная плашка "локальный режим"», и это читалось как вранье. Теперь `dotTone` берёт состояние только у `core`, а плашка называет ту же связь словами: ядро молчит - «нет связи с ядром» красным, ядро отвечает - «локальный режим». Владелец: «шарик у заголовка плагина "BOOK->SKILL" - красный! Значит плашка под ним должна выводить - "нет связи" и быть розового цвета... но плашка зеленоватая и надпись "локальный режим"».
- **Плашку «нет связи» лепит ЗАЛИВКА ИНЛАЙНОМ, а не класс варианта - и без рамки.** `variant: 'bad'` у Badge SDK не существует вовсе (`default|muted|success|warn|destructive|outline|solid`), поэтому плашка выходила прозрачной: цвет молча не подставлялся, и владелец видел «то же самое, что и было». Перешли на `destructive`, но у него фон всего 10% красного (`bg-destructive/10`) и на тёмной теме не читается - теперь заливка инлайном (`rgba(220, 38, 38, 0.32)`). Рамку владелец отменил: «красную границу выводить не надо». Существование любого варианта Badge в SDK сторожит тест.
- **Вертикаль текста в плашке правится АСИММЕТРИЕЙ отступов, а не сдвигом (`transform`/`relative`).** Владелец: «осталось только отцентрировать внутри плашки текст - по вертикали - ну поднять текст на 1 пиксель выше». Базовый `py-0.5` даёт 2 px сверху и снизу - поставлено 1 сверху / 3 снизу: строка поднялась на 1 px, высота и подложка не сдвинулись.
- **Имя скилла предлагается ПОСЛЕ разбора**: `suggested_name` из `/rerun` (эвристика ядра `suggest_skill_name`); первая ручная правка закрывает подстановку (`nameTouched`), подпись «подставлено по источнику - переписать можно тут же».
- **Загрузка не заменяет пайплайн апстрима**: фетчер создаёт `.md`/`.txt`, дальше неизменённый `scripts/extract.py`.
- **Локальный источник - родным путём апстрима, не фетчером**: `resolve_input_files()` сети не делает; фетчер локальный путь не берёт (баг `urlopen` -> `unknown url type: d`); путь берёт плагин `local-file` и делегирует в `book_to_skill.utils.extract_single_file` - формат: `SUPPORTED_EXTENSIONS` + магия `%PDF`, `PK` -> `mimetype`/`word/document.xml`. Своё - только не-utf8 (cp1251/cp866) и каталог (склейка `.md`/`.txt` по алфавиту).
- **Чужой движок сначала изучаем**: `config.py`, `utils.extract_single_file`, `dependencies.prepare_dependencies`, `cli.py`; признак дублирования - своя таблица расширений, свой «detect format», второй реестр парсеров.
- **Панель - штатный desktop-плагин Hermes** (`desktop-plugins/b2s/plugin.js` + REST `plugins/b2s/dashboard/plugin_api.py`), не HTML-виджет: кнопки собирают интент и шлют в сессию (RPC `prompt.submit`); `dashboard/widget.html` - автономный предпросмотр.
- **Имя скилла и slug источника разведены**: имя - как скилл называется и лежит (`skills/<категория>/<имя>/`), редактируемое, из `suggest_skill_name()` (приоритет: сегмент URL -> заголовок -> имя файла); slug (`docs-python-org-3-library-pathlib-html`) - метка сырья для файлов и `staging/`, read-only. **Имя - максимум три слова**: сайт 1 слово, теме 2; служебные слова (`po`, `iz`, `how`, `to`) и числовые хвосты (`-186253740`) выбрасываются; из темы - ГОЛОВА и самое длинное из ОСТАЛЬНЫХ, из заголовка - начало; версия сохраняется (`csharp-13`). Дословно - архив.
- **Панель НЕ предзаполняет имя**: поле пустое или из `ctx.storage`, хардкод `python-pathlib` из `useState` убран; эвристика - в ядре.
- **Пустое имя - обязательный вход, панель это ПОКАЗЫВАЕТ**: поле и подпись жёлтые (`WARN_YELLOW` = `#f59e0b`), «имя скилла не может быть пустым!», «ДАЛЕЕ» блока 1 погашена, тултип «нужно имя скилла: пустым не поставим», `next1` не пускает, если имя стёрли после; подпись «такого скилла нет - будет создан новый». Красная рамка блока 3 - только после пройденного блока 2; до этого он нейтрален.
- **Рамка состояния - как у чипсы `DESCRIPTION.md`**: `border: '1px solid ' + WARN_YELLOW` (как в `catTone`); `borderColor` + `boxShadow: inset 0 0 0 1px` запрещены.
- **Дефолты виджета**: режим движка - `technical - таблицы и код`; галочка «Показывать предполагаемый скилл до записи» включена; цена - модалкой `askDraft()` при нажатии кнопки генерации/перегенерации, не тумблера.
- **Источник вводится полем** (URL или путь, файл/папка); две кнопки-ярлыка (`Button size='icon-xs'` 24×24, `shrink-0`; подписи «Выбрать файл» / «Вставить из буфера обмена» в `title`/`aria-label`) - цветной эмодзи `📂`/`📋` инлайном (`fontSize: 13, lineHeight: 1`).
- **Файл и буфер берут штатные двери Electron:** `window.hermesDesktop.selectPaths({ multiple: false, filters, title })` (IPC `hermes:selectPaths`, полные пути; фоллбэк `<input type=file>` + `getPathForFile` отдаёт только имя - оно в тост, путь просят руками) и `window.hermesDesktop.readClipboard()` (IPC `hermes:readClipboard` -> `clipboard.readText()`; фоллбэк `navigator.clipboard.readText()` отказывает при расфокусе). Двери - в `electron/preload.ts` и `src/global.d.ts`, плагин в главном окне (blob-`import()` в `runtime-loader.ts`); отказ, пустой буфер, отмена - тост `host.notify({ kind, message, detail })`. Дословно - архив.
- **Схема интента (≤500 символов, лимит моста `::preview`)**: `b2s <kind> | src= | name= | strat= | mode= | depth= | lang= | cat= | slug= | draft=0|1 | won= | junk= | model=` (замер на pathlib - 275; `src=` заменил `url=`). Ветка категории: `b2s desc | cat= | dmode=write|fix | desc=`: `write` - файла нет, `fix` - без frontmatter, прежний текст сохраняется телом.
- **Действия - один нумерованный блок из трёх шагов**: 1 «Прогнать источник заново» (`rerun`, кнопка у поля источника, файлы скилла не пишутся) -> 2 «Сделать черновик» (`draft`, платная генерация в `staging/`, одна кнопка на заход и переделку, подпись «Перегенерировать с учётом замечаний») -> 3 «Установить» (`install`, перенос в `skills/<категория>/<имя>/`, гаснет без черновика); «Разобрать черновик» (`review`) - в блоке черновика.
- **Уборка рабочих каталогов, но не молча**: черновик - `staging/<слаг источника>`, сырьё - `b2s_fetched/<слаг>.*`; установленный - архив с TTL (`STAGING_TTL_DAYS = 7` дней), свежие - лимит (`STAGING_KEEP = 5` сверх активного), `_probe*` не трогаем, `reason` называет причину. Двери: автоуборка при открытии панели `POST /prune {keep: 99, days: 0, apply: true}` (лишь TTL); строка «рабочие каталоги в staging» в блоке 3 (число файлов, «установлен», корзина - `POST /drop`); кнопка «Убрать лишнее» (`POST /prune` без `keep`). Пометку ставит `_mark_installed` в `metadata.json`; активный - слаг = `src` или `source.url`; каталоги по имени скилла защищены.
- **Реквизиты ЗАПИСИ - в блоке 3**: «Категория скилла» (с описанием), «Имя скилла», список скиллов категории; блок 1 требует один вход - источник. **Ядро дописывает `name:` в шапку `SKILL.md` при установке** (`_retitle_skill_md`, ДО копирования staging->target), иначе каталог разъезжается с шапкой.
- **Маркер авторства - `creator`/`created`/`updated` внутри `metadata.hermes`** (`_stamp_hermes_meta`, до копирования): `creator: BookToSkill`, `created` - один раз, `updated` - всегда; верхним уровнем - 3 warning линзы `hermes`, в `metadata.hermes` - 0. В промпт идёт только `- {name}: {description}` (`prompt_builder.py`, `available_skills` -> `index_lines`). **Метку ставит только ядро при установке через панель: чужим скиллам профиля (128 файлов `SKILL.md`, из них наших 3) ничего не дописываем** - `creator: BookToSkill` у скилла, собранного руками, был бы подлогом.
- **Служебные файлы ядра в скилл не едут**: `merge-plan.json` фильтрует `_SERVICE_FILES` (`ignore=` при копировании), в `staging` остаётся; из трёх скиллов профиля удалён.
