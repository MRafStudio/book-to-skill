# Тесты проекта (book-to-skill, наш форк)

**Эти тесты не сжимаются и не выносятся в архив.** Они и есть проверка: и ядро b2s
(`tools/api.py`), и панель (`hermes/desktop-plugins/b2s/plugin.js`), и установка скиллов.
Журнал (`BOOK-TO-SKILL/HERMES.md`) на них только ссылается - чтобы не тратить его
бюджет (30 720 символов на контекст-файл).

## Как запускать

Полный прогон - **интерпретатором профиля**, в нём есть `trafilatura` и `fastapi`:

```bash
cd D:/.VS/Projects/BOOK-TO-SKILL/_fork
# весь пакет сразу (печатает итог и код возврата):
"D:/NEURO/Hermes/data/hermes/hermes-agent/venv/Scripts/python.exe" tools/tests/run_all.py
# один тест:
"D:/NEURO/Hermes/data/hermes/hermes-agent/venv/Scripts/python.exe" tools/tests/test_<имя>.py
```

Один файл - так же, по имени. Код возврата `0` = зелено; сами тесты печатают
`проверок: N, провалов: M`. Прогонять полный набор **после каждой правки плагина или ядра** -
это часть работы, а не формальность.

Системный `python` для части тестов **не годится**: `test_md_tables` и `test_plugin_install`
падают на `ModuleNotFoundError: trafilatura / fastapi` - это не поломка кода, а чужой интерпретатор.

## Что держат файлы (по группам)

**Ядро (`tools/api.py`)**
- `test_category_desc.py` - категории и описания: состояния `ok` / `no-frontmatter` / `no-file`,
  запись `desc` (режимы `write` / `fix` / `rewrite`), враждебный ввод за пределы `skills/`.
- `test_chapter_plan.py`, `test_draft_desc.py`, `test_install_modes.py`, `test_local_source.py`,
  `test_retitle.py`, `test_skill_name.py`, `test_staging_cleanup.py`, `test_sources_journal.py` -
  план глав, описание черновика, режимы установки (в т.ч. долив), локальный источник,
  перенос имени в шапку, валидация имени, уборка staging, источники в журнале.
- `test_md_tables.py` - фикс таблиц: разделитель вставляется, корректная таблица не портится,
  конвейер `clean_html` пропускает вывод извлекателя через фикс.
- `test_plugin_install.py` - установка плагина в профиль (сверка хешей).

**Панель (`plugin.js`)** - вырезают функцию из ЖИВОГО файла и исполняют её в node,
то есть проверяют поведение, а не текст:
- `test_plugin_syntax.py` - разбор файла ЦЕЛИКОМ (фрагментный тест аварии в другом месте не видит);
- `test_pane_blocks.py`, `test_pane_block4.py`, `test_pane_head.py` - блоки, шапка, состояния;
- `test_pane_name.py` - нормализация имени и подсветка поля (рамка: красная при ошибке,
  оранжевая при предупреждении; цвет подписи не меняется);
- `test_pane_src.py`, `test_pane_draft.py`, `test_pane_draftkey.py` - источник, черновик, ключ черновика;
- `test_pane_watch.py` - вотчер описания категории (интенты `desc` / `desc-fix` / `desc-rewrite`);
- `test_pane_mode_badge.py` - плашка режима (`Работает LLM...`), точка статуса (зелёная при живом ядре);
- `test_pane_purge.py` - урна: `POST /purge` + сброс полей панели (источник и категория остаются);
- `test_pane_catdesc.py` - кнопка описания категории во всех трёх состояниях, включая «Пересоздать»;
- `test_pane_cleanup.py` - кнопки уборки.

## Если тест держит устаревшую строку

Сторожа панели текстовые: они ищут конкретные подстроки в живом `plugin.js`. Когда
формулировка в панели меняется по просьбе владельца, падает соответствующий сторож -
правится **вместе с кодом**, а не отключается.
