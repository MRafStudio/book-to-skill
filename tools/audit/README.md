## `links.py` - граф перекрёстных ссылок внутри ОДНОЙ категории

Универсален: работает с любым каталогом скиллов, никаких меток плагина не требует.
Читает все `.md` каждого скилла, ищет имена СОСЕДЕЙ ЭТОЙ ЖЕ категории в бэктиках и
строит направленный граф.

```
python tools/audit/links.py --skills-dir skills/<категория>            # только чтение
python tools/audit/links.py --skills-dir skills/<категория> --apply    # + записать related_skills
python tools/audit/links.py --skills-dir skills/<категория> --json     # машинный вывод
```

Даёт: число рёбер, таблицу «кто на кого», хабы по входящим, сирот (на них никто не
ссылается), молчунов (сами никого не упоминают) и расхождения между заявленными
связями (`related_skills` в шапке, `cross_refs` в `metadata.json`) и фактическими.

`--apply` пишет `related_skills` по факту графа - **только между скиллами этой
категории** (соседи из других категорий в граф не попадают по построению).

Из ядра то же самое: `python tools/api.py audit-links --cat <категория> [--apply]`.

## `toc.py` - покрытие источника (сейчас только Confluence)

Показывает, какие страницы источника имеют скилл, а какие нет. Требует адреса
источника у скилла: `source_url` в шапке или `source.url` в `metadata.json`.

```
python tools/audit/toc.py --space RK7 --skills-dir skills/rk7xml-interface --root-page 19605640
python tools/audit/toc.py --space RK7 --skills-dir skills/rk7xml-interface --search RK7Query
```

**Оговорка:** сбор оглавления сделан под Confluence (`/rest/api/content?spaceKey=...`),
поэтому для не-Confluence источников (обычный сайт, локальный каталог) нужен свой
провайдер оглавления - см. журнал, раздел «Решения».

## Грабли, проверенные на себе

- **Источник скилла лежит в двух местах:** `source_url` в шапке или `source.url` в
  `metadata.json`. Читать надо оба, иначе половина каталога выглядит непокрытой.
- **Читаемый URL получай РЕДИРЕКТОМ** (`/pages/viewpage.action?pageId=...`): слаг
  транслитерируется, склеенный руками адрес даёт 404.
- **Вставка строки в CRLF-файл.** Скиллы профиля записаны с CRLF: при правке через
  `split("\n")` / `join("\n")` у новой строки не будет возврата каретки - файл станет
  смешанным. `links.py` берёт перевод строки от самого файла.
